# Decisions

One line per decision: the decision, then the reason.

- The product requirements document lives in `PRD.md`, not `PRODUCT_REQUIREMENTS.md` as the build prompt says; kept the provided filename and referenced it as the PRD everywhere — renaming supplied files risks breaking external references.
- Dependency installation (`npm install`) was skipped per user instruction after repeated registry timeouts; the full dependency manifest and lockfile-less manifest were written, but phase-gate commands cannot run until dependencies are installed — respect the user's explicit instruction and keep progress visible.
- `cacheComponents` and `partialPrefetching` were disabled in `next.config.ts` — role layouts and API routes need `headers()`/`cookies()`, which require Suspense boundaries under cache components; a banking dashboard is dynamic by nature.
- `serverExternalPackages: ["mongoose", "mongodb"]` was added — native/driver packages must not be bundled by Turbopack on the server.
- Account type is fixed at opening; only the nickname can be edited later — changing the type would change the account number format and limit defaults, so it would be a new account.
- CSV/ PDF amounts are written as `BDT` plain decimals rather than the ৳ glyph — standard PDF fonts do not include the Bengali currency glyph.
- HeroUI v3 calculated colors were verified against `variables.css` in the upstream v3 source (`--accent-hover`, `--accent-soft`, `--accent-soft-foreground`, `--success-soft`, etc.); our unlayered theme overrides them and derived hovers inherit the new source values — node_modules is unavailable locally.
- Navigation links that look like buttons use the documented `.button button--primary|ghost|outline` BEM classes instead of `<Button as={Link}>` — HeroUI v3 removed `asChild` and documents a `render` prop, so styling an anchor avoids relying on an unconfirmed polymorphic API.
- Money, mask, and time utilities were created in Phase 2 rather than Phase 3 — the UI primitives need them immediately; their unit tests land in Phase 3 (done).
- Phase 6: services take `Actor | null` because routes pass nullable actors and `assertRole` narrows at runtime (`build.mutation`'s inferred arg type was `ApiError`); RTK v2 mutation results have no `isPending`, so components check `result.status === "pending"`; the staff customer page uses only "Unblock" (block is admin-only via the service + route; the admin customers page lands in Phase 10); password compensation on staff-register uses the trusted `AuthUser.collection.deleteOne({ email })` because the read-only user model throws on delete operations; `CustomerDto.createdAt` was added for the staff detail page; badges use `as StatusKind` casts because `kyc:${string}` template literals don't satisfy `StatusKind`; `admin/accounts/[id]` updates limits with `Math.round(Number(taka) * 100)` since the form sends taka strings.
- The `server-only` sentinel is aliased to an empty module in Vitest and scripts run with `NODE_OPTIONS=--conditions=react-server` — the package throws outside a React Server Component bundle, but tests and seed/verify scripts run in plain Node.
- System accounts use fixed leading-zero account numbers and are excluded from customer lookups — they must never be reachable as transfer recipients.
- The last EMI installment absorbs rounding so principal components sum exactly to the principal — required by the §8.6 invariant.
- `payoffMinor` sums unpaid principal only, with no future interest — specified by the §8.6 payoff mode.
- Phase 5: the global progress bar derives its width from `ui.pendingRequests` instead of the delayed `visible` state — the `react-hooks/set-state-in-effect` rule forbids the synchronous setState in the effect body; toasts come from a small client-side emitter (`src/lib/toast.ts`) plus `ToastStack`, not a state slice, because Redux actions can't use React context; each role's `StoreProvider` creates the store in `useMemo` and seeds `auth` from the session user the layouts pass; per-endpoint `pollingInterval` is not allowed on RTK 2.x query definitions (it lives in `SubscriptionOptions`), so the unread-count bell polls via the hook's options and `setupListeners` runs from `StoreProvider`; `errorMiddleware` navigates with an absolute-URL `window.location.assign` to satisfy the `no-location-assign-relative-destination` lint rule.
